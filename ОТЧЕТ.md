✅ Выполненные задачи:
1. Создание схемы базы данных

Спроектированы 4 основные сущности:
users (пользователи: клиенты, менеджеры, админы)
brands (справочник марок автомобилей)
cars (автомобили в салоне)
orders (заказы на покупку)

2. Нормализация до 3NF

1NF: Все поля атомарные, у каждой таблицы есть PRIMARY KEY
2NF: Все неключевые поля зависят от всего первичного ключа
3NF: Устранены транзитивные зависимости (brand вынесен в отдельную таблицу)

3. Настройка связей

FOREIGN KEY: cars.brand_id → brands.id
FOREIGN KEY: orders.user_id → users.id
FOREIGN KEY: orders.car_id → cars.id

4. Ограничения целостности

UNIQUE: users.user_name, users.email, brands.name
DEFAULT значения для role, is_active, status, created_at

5. ER-диаграмма

Создана визуальная схема связей (dbdiagram.io)
Отображены все отношения 1:N

6. Master-Slave репликация PostgreSQL 18

Настроен Master (порт 5432) для записи
Настроен Slave (порт 5433) для чтения
Конфигурация: wal_level = replica, max_wal_senders = 3
Проверка: pg_stat_replication показывает state = streaming
Slave подтверждает: pg_is_in_recovery() = true
Результат: Данные синхронизируются в реальном времени (<1 сек задержка)

7. Raw SQL функции для авторизации

register_user(user_name, email, password_hash, phone)
  → Возвращает: user_id, created_at
  → Обработка ошибок: unique_violation

verify_login(email, password_hash)
  → Возвращает: id, user_name, email, role, is_active
  → Проверка существования пользователя

8. Индексы для ускорения поиска

idx_users_email → быстрый поиск по email при логине
idx_users_username → проверка уникальности имени
idx_cars_brand_id → фильтрация по марке (Index Scan, 0.339ms)
idx_cars_price, idx_cars_year, idx_cars_status → сортировка и фильтрация
idx_orders_user_id, idx_orders_car_id → JOIN оптимизация
